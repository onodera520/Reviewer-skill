# 提示词与预览口径对照

机器测试入口：`python -m unittest discover -s evals -p 'test_*.py'`。test_story_preview.py 验证提示词绑定、缺失、冲突、版本、旧记录兼容、声音排除和报告字段；媒体测试实际解码并确认没有音频提取命令。这些测试不自动判断图像含义。

视觉回归使用不含答案的独立上下文，给每张图提供明确绑定的测试提示词。以下是维护者评分条件，不作为 Reviewer 的观察证据：

| 对照 | 预期 |
| --- | --- |
| 提示词为拿起便当，图中伸手抓取尚未离层板 | 意图清楚则通过；不声称已经拿离 |
| 相同提示词，改成拿杯子或放回关键对象 | 报告对象或方向错误 |
| 明确已经把便当交给店员，但仍全在主角手中 | 必要结果错误，不能用准备动作替代 |
| 同一货架清晰可见且满载变空 | 保留连续性问题；按影响分级，不自动 high |
| 同货架离画、被遮挡或商品包装轻微变化 | 不报消失 |
| 相同图，交换两张图的对应提示词 | 不借用另一张提示词判通过；绑定不明先待确认 |
| 缺提示词／提示词与 Spec 核心意图相反 | 有限检查，符合性 uncertain／REVISE |
| 视频仅音轨或水印不同 | 不触发额外处理或判定变化 |
| 视频动作意图成立，小幅动作及压缩时长 | 通过；必要因果仍应成立 |

用户的便当示例可用于人工检查阶段容差，但未提供完整原始提示词时，不宣称已完成该图的提示词符合性审查。若自建“男人伸手拿起便当”等测试提示词，必须明确是受控测试文本，不伪装成用户原文。

新旧 profile 的结果不能混合计算准确率；旧素材可重用，新评测另存，不覆盖历史报告。不把契约通过或提示词规则文本检查宣称为盲评成功。

数量专项使用 quantity/inputs.json 与其相对 media 文件。该清单为评测输入，不是运行时 ReviewInput；执行者只接收清单、媒体和 Skill。quantity/truth.json、构建脚本与 [维护者实看记录](quantity/observations.md) 不提供给盲评执行者。至少覆盖两盒四边缘、内部结构、遮挡、真实四盒和重复源图视频；按原始分辨率核实独立盒体，不以测试名称或预期答案计数。
