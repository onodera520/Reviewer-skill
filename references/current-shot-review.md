# 单镜合规审查

## 依据与静态目标

当前 Shot Spec 是当前图片合规的依据。绑定资产补充身份和固定形态；原始 Image Prompt 用于发现漏译、转写冲突，不覆盖 Spec。Spec 与绑定资产矛盾时记录输入冲突及所需版本依据，受影响项 `uncertain`，不擅自选一个作为定稿。

先明确 Spec 要呈现的一个静态画面。Generator 输入另按 [兼容规则](generator-compatibility.md) 读取 `storyboard_keyframe.camera_state`、`composition`、`blocking` 和 `state`；顶层起始／结束摄影与动作状态不能替代关键帧。核对适用于该静态目标的 `must_have`、`must_not_have`、资产绑定与光色约束。保留输入结构，不修改 Generator。

多状态描述未指定静态目标时，不擅自选择动作开始或完成后的状态。受影响检查 `uncertain`，请求明确关键帧；不妨碍其他确定属性的核对。仅适用于视频的约束跳过，不产生视频审查结果。

## 检查表

| 方面 | 核对内容 |
| --- | --- |
| 静态叙事事实 | 本图应表达的人物状态、动作姿态、表情、视线及剧情结果是否可辨 |
| 人物和资产 | 身份、人数、固定外观、服装、配饰、资产版本；不可辨认的细节不猜测 |
| 道具 | 关键道具、剧情数量、角色自身手别、持有者、位置和状态 |
| 空间与构图 | Spec 指定机位、景别、取景、朝向、地标关系、必现元素；只判断静态图 |
| 场景与背景 | 场景身份、固定结构、明显物件及指定状态 |
| 光色与环境 | 日夜、光源、灯具开关、天气、指定色调及既定场景结果 |
| 硬约束 | 所有适用于图片的 must_have / must_not_have；排除视频专属约束 |

单镜问题的 `error_type` 使用 `shot_spec_compliance`，在状态描述与 reason 中说明是人物、道具、构图或其他约束不合规；同时涉及连续性的同源问题使用连续性类别并关联两个分项。缺输入是 uncertainty，不是实际图像错误。

## 可见性和证据

实际看图后才能声称物件缺失、身份改变或状态错误。看不到隐藏区域不能证明实体不存在。如果 Spec 明确要求完整展示某物，而实际图裁掉它，记录展示／构图不合规，不推断世界中的物件消失。

单镜问题至少给出 Spec／资产约束和当前实际图像证据。位置使用可复查描述，不虚构像素测量。权威要求未给出时，不能以审美偏好增加要求；普通渲染随机性不计错。

默认 Markdown 只呈现问题、严重程度和修改方案，但内部 issue 仍须保留完整依据。`recommended_fix` 应指出修复镜头和必须恢复的既有事实。若原 Image Prompt 可通过补充明确约束解决，附上一条可直接使用的中文提示词修改方案；不得靠改景别、机位或人物安排遮蔽错误。问题来自错误资产、冲突版本或图片后期时，说明真实修复对象，不生造提示词。

当同一错误同时违反当前 Spec 与连续状态时，仅建一条 issue，主 `review_area` 使用 `cross_shot_continuity`，`related_review_areas` 包含 `current_shot_compliance`，提供两套依据，并使两个分项均反映错误。

若当前图和 Spec 一致、但前镜图错误，当前合规仍可 PASS；按连续性模块定位前镜问题。不得让错误前镜迫使正确当前图变错。
