# 报告交付

## 默认成品

默认交付一个干净的中文 UTF-8 Markdown（.md）文件，方便用户直接阅读和转交修复。保留 PASS / REVISE / REGENERATE 最终判定；静态两项与智能分镜三层按实际审查模式展示。呈现形式不改变内部 Schema、证据标准、严重程度、归因或状态继承规则。

路径优先遵循用户指定；否则使用当前工作目录的 `review.md`。已有同名文件且本次不是明确修订该报告时，选择 `review-02.md`、`review-03.md` 等首个不重名文件，不覆盖已有成品。

## 内部记录与生成

1. 内部维护完整归一化输入及符合契约的完整报告。不要因成品精简而省略状态、证据、覆盖范围或不确定项。
2. 将报告保存到成品所在目录的 `.reviewer/<报告文件主名>.json`，例如 `review-02.md` 对应 `.reviewer/review-02.json`。归一化输入可保存在同目录的 `<报告文件主名>.input.json`；固定输入资源路径后再保存，避免移动输入 JSON 改变相对图片路径含义。
3. 使用 [render_review.py](../scripts/render_review.py)：`python scripts/render_review.py --input normalized-input.json --report full-report.json --output review.md`。参数替换为实际路径；脚本先校验输入／报告契约，再确定性生成成品。未通过校验时修复内部记录，不能绕过校验输出貌似已核实的报告。
4. 实际读取成品，确认没有原始 JSON、技术字段、空章节或调试文字，并核对证据与修复建议没有被省略或改义。
5. 最终对话仅简短提供成品的可点击绝对路径链接，不重复报告正文，不默认链接或展示内部缓存。

`.reviewer` 是内部状态目录，点前缀用于区分成品，不等于操作系统一定隐藏它。下一镜或续批显式读取相关缓存的 persistent_visual_state 作为输入；不得仅凭对话记忆或 Markdown 摘要重建事实。修订报告时同步对应内部记录。跨目录转交时需携带该记录才能完整续接状态；没有它则按实际可用材料重建并说明覆盖限制。

## 成品内容

仅静态审查时按下列顺序显示，仅包含有内容的区块：

1. 标题：“SHOT_02 静态分镜审查”。
2. 简短结果表：总体结论保留 PASS / REVISE / REGENERATE，分别显示“当前分镜合规”“跨镜视觉连续性”。分项翻译为“通过／不通过／待核实／不适用”，不暴露字段名。
3. 已确认问题：每个问题使用中文类别与严重程度标题；必要时写出涉及镜头及应修复的镜头。依次给出“前镜状态”（存在时）、“预期状态”“实际状态”“证据”“原因”“建议修复”。证据保留可核对的镜头和画面区域；下一镜比较按实际目标镜头表述，不把后镜错误说成当前镜错误。
4. 待核实项：明确待核实的问题、已有证据（存在时）、不能确定的原因及所需补充材料，不伪装成已确认错误。
5. 审查限制：仅列影响结论或覆盖范围的缺图、模糊、版本冲突等实质限制。普通未提供的可选输入不制造无意义警告。
6. 必要说明：只保留对用户理解或修复有帮助的低严重度说明，省略内部处理日志和状态维护过程。

没有问题时不展示空的问题列表；没有不确定项或限制时不展示空章节。不得在成品中展开 persistent_visual_state、visibility_checks、state_invalidations、source_version、fact_id、issue_id 等技术数据，也不粘贴 JSON／Schema／命令行／调试日志。来源版本仍保留在内部证据；若版本冲突影响审查，以中文说明实际冲突与所需材料。

## 智能分镜及合并报告

视频模式以“智能分镜审查”为标题，先给总体结论，再给“视觉锚点一致性／动态执行一致性／镜头序列一致性”三层结论表，最高优先级为视觉锚点。逐项问题使用用户可识别的镜头号和实际视频时间点／范围，显示预期、实际、证据、原因、建议修复对象及范围。时间采用可读的分秒表示，保留定位短镜或切点所需精度；不得展示未经映射核实的来源时间为实际视频时间。

同时审图和视频时顺序为：总体结论 → 静态分镜审查 → 智能分镜审查 → 必要待确认项与覆盖限制。静态章节保留各镜合规与连续性结果；同因源图／视频错误说明其继承关系，避免重复建议。仅审视频时省略无关静态章节，发现源图问题仍在相关问题中指出，不能因省略章节隐去来源错误。

不加入原视频入口、链接或可播放预览；证据用“镜头 03 · 00:02.480–00:02.760 · 右手区域”等可核对文字表达，不把视频 ID 或文件路径变成入口。也不展示抽帧清单、内部 JSON、状态账本、state_snapshots、原始音频检测值或技术日志。覆盖限制只说明哪些镜头／声音／区间尚未核验及对结论的影响，不把已解码表述成已完成审查。

## 用户明确要求其他格式

用户明确要求 JSON／完整结构化数据时，交付符合原输出 Schema 的完整 JSON，包括持久状态；不以 Markdown 摘要代替。用户明确要求只在对话展示时，可直接给同样干净的 Markdown 正文；否则默认写文件并仅返回链接。不得自动输出两套重复报告。
