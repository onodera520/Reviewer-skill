# 报告交付

## 默认成品

默认交付一个干净的中文 UTF-8 Markdown（.md）文件，方便用户直接阅读和转交修复。保留 PASS / REVISE / REGENERATE 最终判定；正文只显示用户采取修改行动所需的最少信息。静态分项、智能分镜三层结果、完整证据、覆盖范围、归因与状态仍保存在内部报告，精简呈现不降低审查标准。

路径优先遵循用户指定；否则使用当前工作目录的 `review.md`。已有同名文件且本次不是明确修订该报告时，选择 `review-02.md`、`review-03.md` 等首个不重名文件，不覆盖已有成品。

## 内部记录与生成

1. 内部维护完整归一化输入及符合契约的完整报告。不要因成品精简而省略状态、证据、覆盖范围或不确定项。
2. 将报告保存到成品所在目录的 `.reviewer/<报告文件主名>.json`，例如 `review-02.md` 对应 `.reviewer/review-02.json`。归一化输入可保存在同目录的 `<报告文件主名>.input.json`；固定输入资源路径后再保存，避免移动输入 JSON 改变相对图片路径含义。
3. 使用 [render_review.py](../scripts/render_review.py)：`python scripts/render_review.py --input normalized-input.json --report full-report.json --output review.md`。参数替换为实际路径；脚本先校验输入／报告契约，再确定性生成成品。未通过校验时修复内部记录，不能绕过校验输出貌似已核实的报告。
4. 实际读取成品，确认没有原始 JSON、技术字段、空章节或调试文字；核对问题概述没有歪曲内部证据，修改方案足以直接执行。
5. 最终对话仅简短提供成品的可点击绝对路径链接，不重复报告正文，不默认链接或展示内部缓存。

`.reviewer` 是内部状态目录，点前缀用于区分成品，不等于操作系统一定隐藏它。下一镜或续批显式读取相关缓存的 persistent_visual_state 作为输入；不得仅凭对话记忆或 Markdown 摘要重建事实。修订报告时同步对应内部记录。跨目录转交时需携带该记录才能完整续接状态；没有它则按实际可用材料重建并说明覆盖限制。

## 成品内容

仅静态审查时按以下格式显示：标题、总体结论，以及每个已确认问题的“问题、严重程度、修改方案”。问题概述将实际错误和应恢复的状态合成一句；连续性问题仅在理解错误所需时带上前镜已建立状态。省略分项表、逐条证据、判断过程、素材编号、普通说明和覆盖日志。

修改方案必须能直接执行。适合通过提示词修正时，在 `recommended_fix` 中给出保持原设计的具体提示词增补或替换，例如“提示词补充：‘柜台右后方三层货架保持满载饮料和零食，层板不得为空’”，同时说明重生成哪个镜头。若问题来自资产、源图、局部编辑或输入冲突，说明对应修复对象，不强行给无效的提示词方案。提示词建议只能明确既有 Spec 与正确连续状态，不能新增设计。

证据不足不混入已确认问题，使用简短“待确认”：可能严重程度、待确认问题、下一步所需材料。影响结论的缺图、模糊、版本冲突或覆盖缺口必须在内部形成 uncertainty，不能只写在 coverage 后被精简报告隐藏。没有问题和待确认项时只写“未发现需要修改的问题”。

不得在成品中展开 persistent_visual_state、visibility_checks、state_invalidations、source_version、fact_id、issue_id、分项状态或技术覆盖字段，也不粘贴 JSON／Schema／命令行／调试日志。

## 智能分镜及合并报告

视频模式显示总体结论和紧凑的问题卡片。每条只保留“镜头号 + 已核验的视频时间范围、严重程度、问题、修改对象、修改方案”。问题一句话说明实际表现和正确目标；时间采用可读分秒并保留定位短镜或切点所需精度。未经映射核实的时间不得显示为实际定位。

三层审查仍完整执行，但默认 Markdown 不展示三层结论表、逐镜映射表、参考时刻表或逐条证据。问题涉及几个层级只记录一次；用户通过镜头和时间直接找到画面，通过修改对象判断应修源分镜图、指定视频镜头、剪辑还是声音。修改方案必须给出可操作范围，例如“删除 00:01.200–00:01.360 的叠化帧并在两侧清晰帧处硬切”，或“重生成 SHOT_04，保持人物右手两个便当袋贯穿该镜”。

同时审图和视频时顺序为：总体结论 → 静态分镜问题 → 智能分镜问题 → 必要待确认项。静态部分仍采用三字段格式；同因源图／视频错误说明依赖关系并避免重复建议。仅审视频时省略静态章节，发现源图问题仍在智能分镜问题的修改对象中指出。

不加入原视频入口、链接或可播放预览；也不展示抽帧清单、内部 JSON、状态账本、state_snapshots、原始音频检测值或技术日志。无法完成的镜头映射、声音或覆盖核验以“待确认 + 下一步”表示；仅有内部 coverage 说明不能替代 uncertainty。

## 用户明确要求其他格式

用户明确要求 JSON／完整结构化数据时，交付符合原输出 Schema 的完整 JSON，包括持久状态；不以 Markdown 摘要代替。用户明确要求只在对话展示时，可直接给同样干净的 Markdown 正文；否则默认写文件并仅返回链接。不得自动输出两套重复报告。
